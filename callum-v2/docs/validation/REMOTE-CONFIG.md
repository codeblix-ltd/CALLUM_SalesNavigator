# Remote config validation

Environment: V2 Cockroach schema and a running unpacked V2 extension in an isolated Chrome session. Baseline SHA: `68f5971a5e4b91d0814cd0f2b32dd18dbd64237b`.

`pnpm test` rejects unknown config fields, executable-like selectors, unbounded waits and unsafe labels. `V2_TEST_DB=1 node --env-file=<local server env> --test tests/remote-config.integration.test.mjs` passed draft activation, pending-command version update, rollback and operator kill, including resumption after the flag cleared. An MCP shadow smoke changed dev config from version 1 to 3: the same running extension reported version 3 and completed a new observation command without rebuild or reload. The script rolled dev back to version 1. After the authenticated read-only H2 layout finding, `node --env-file=<local server env> scripts/activate-default-config.mjs` activated current source selectors as **dev config version 6**; stable remains version 1. Earlier test configs remain for audit.

This proves server-to-running-extension delivery and schema-checked data loading. The isolated browser redirected to LinkedIn's authwall, so the changed selector's effectiveness on an authenticated target card remains unproven. Config data contains no remote JavaScript or executable DSL. Global/connection/comment/withdrawal/contact, operator, cohort, version and config kill keys are represented server-side; only the implemented action command is currently issued by the workflow.

After adding optional post/contact selector families, `activate-default-config.mjs` activated **dev config 10**, minimum extension `2.1.0`; stable remains on config 1. Cockroach rejected a 2.0.0 installation against the dev config. The running 2.1.0 extension reported config 10 in the final shadow smoke. The target layout remains unverified behind LinkedIn authwall.
