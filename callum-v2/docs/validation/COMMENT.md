# Reviewed comment action validation

Implementation commit: `b4e9668aba01ebdd11a31abe1e4b76a4a8e46a29`. Packaged MV3 version `2.4.0`, adapter `5`, build SHA `b4e9668aba01`. Dev config `24` requires 2.4.0; stable/canary remain on config 1. Migration `004_comment_action` affects only `callum_v2` and passed a repeat application.

The admin creates a draft from a completed scoped comment inspection and explicitly approves or rejects its exact text. Approval requires a `live_canary` run for `V2_QA_PROFILE_KEY`, a bound installation actor profile, and a matching observation from that installation within two minutes. It reserves one intent per operator, lead, and post, then queues one `EXECUTE_COMMENT`. Authorization checks the approved draft hash, source observation, active config, kill switch, QA scope, lease, and intent. The extension rechecks profile/post author, signed-in actor and existing own exact comment, opens the editor, verifies the text, clicks one submit, and observes the own comment. An uncertain result or expired lease queues only `INSPECT_COMMENT_STATE`; no action is redelivered. A confirmed action or later observation can create one pay line only under an enabled versioned `comment_confirmed` rule. No business rate was configured; the integration used a zero-amount rule and disabled it afterward.
